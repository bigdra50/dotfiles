# 公開文書

公開する文書（README、仕様、API の説明）には、使う人が必要とする仕様と手順だけを書く。
表、式、コマンド、型の定義を中心にし、説明の文は短く添えるだけにする。
設計の段階で書いた文書をそのまま公開すると、決定の理由や検討の経緯が各所に残り、余計なことを書きすぎた印象になる。

## 書かないもの

- 設計の理由と、採らなかった案の説明
- 他製品との比較や「〜と同じ作法である」という補足
- 今後の予定（次の段階で加えるもの）
- 実機で確かめた経緯と測定の記録
- 「実装が始まったら」のような、書いた時点の段階を表す文
- 会話の中の設計の議論に引っ張られた文
  - 位置付けの宣言（〜と同じ作法、〜には依存しない）
  - 実装の内訳（バイト列をそのまま流す、最小の実装を持つ）
  - 依存パッケージのライセンスの注記

## 判断のしかた

- 「この会話を知らない読者が、その文が無くて困るか」で判定する。困らなければ削る
- 理由を 1 文だけ残すのは、それが無いと読み手が誤用するときに限る
- 冒頭の説明が要らない文書は、見出しのすぐ下から本題（使用例や表）を始める
- 見出しは、OSS でよく使われる名詞（Installation、Usage など）にする。「アプリを入れる」「見る」のような動詞の句にしない
- 残したい設計の記録は、コミットしない手元の文書へ書く
