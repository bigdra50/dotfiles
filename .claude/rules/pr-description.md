# PR Description ルール

PR 本文の構成と分量を定める。
タイトル形式・言語ポリシー・自動リンク回避は [commit.md](commit.md) を参照。

## 基本形（10行前後）

1. Why — なぜこの変更が必要か（現状の問題）を1〜2文
2. What — 何をしたかの箇条書き。1項目1行で内容まで言い切る
3. 検討したがやらなかったこと — あれば理由とともに1文
4. 動作確認 — 何をどう確認したかを1文

## 原則

- 本文に書くのは「コードでは語られない情報」だけ: 目的、設計意図、やらなかった選択肢とその理由。diff を読めば分かることは書かない
- タイトルが具体的なら本文は短くてよい。「タイトルどおりです」で済む粒度に PR を切る
- 見出しやテンプレセクション（TL;DR / Files 表など）は使わず、フラットな文と箇条書きで書く
- 人間が書く自然体の文章にする。網羅的な列挙や理由付けの重ね書きをしない
- 短くするときも Why の1文は削らない。削る対象は説明の重複と修飾
- 曖昧語（「もろもろ」、具体例を伴わない「など」）を避ける

## 例

> E2E はこれまで「install が通るか」までしか見ておらず、manifest の警告や配布物への混入は検査していませんでした。
> 無認証のまま足せる検査を2つ追加します。
>
> - marketplace 登録前に `claude plugin validate --strict` — 未認識フィールドなどの warning も fail にする
> - apm install 後に `apm audit` — 不可視 Unicode の混入と、install 後の drift（改竄・破損）を検査する
>
> スキルが実際に発動して動くかの検証も検討しましたが、エージェント実行に認証が必要なため、無認証が前提のこの E2E には入れていません。
>
> クリーンコンテナでフル実行し、ALL PASS を確認済みです。
